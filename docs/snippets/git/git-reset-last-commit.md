# Удалить последний коммит вместе со всеми его изменениями

Команда передвигает текущую ветку на один коммит назад и приводит индекс и рабочую папку к предыдущему состоянию. В отличие от `--soft` и `--mixed`, которые сохраняют изменения коммита в индексе или рабочей папке, `--hard` отбрасывает их безвозвратно.

::: danger Перед запуском
`git reset --hard HEAD~1` передвинет текущую ветку на один коммит назад и приведёт индекс и рабочую папку к предыдущему состоянию. Все незакоммиченные изменения в отслеживаемых файлах будут потеряны. Перед запуском проверьте `git status`; если сомневаетесь, создайте резервную ветку.
:::

```bash
# удалить последний коммит вместе со всеми его изменениями
# осторожно: изменения коммита будут потеряны безвозвратно
git reset --hard HEAD~1
```

::: tip Когда это уместно
- Последний коммит существует только локально и точно больше не нужен
- Нужно вернуться к предыдущему состоянию ветки, отбросив изменения коммита
- Работа ведётся во временной или личной ветке
:::

::: warning Если коммит уже опубликован
Обычный `git reset` изменит только локальную ветку. Не переписывайте общую историю через `git push --force` без согласования с командой: это нарушит работу коллег и потребует от них вручную синхронизировать ветки.

Если в коммите оказался пароль, API-ключ или другой секрет, его нужно немедленно отозвать или заменить. Переписывание истории может сократить дальнейшее распространение секрета, но не делает уже скопированное значение безопасным. Для удаления файла из опубликованной истории используйте специализированный инструмент, например `git filter-repo`, и согласуйте последующий force push.
:::
